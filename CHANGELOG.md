## [v0.3.0](https://github.com/CryptoAPIs-io/cryptoapis-n8n-nodes/releases/tag/v0.3.0) - 2026-08-05

### Added

- `blockchainFees`: Solana support — mempool fee recommendations plus compute-unit
  estimates for native SOL, SPL token, and program-invocation transactions.
- `prepareTransactions`: Solana, XRP, Kaspa and UTXO, behind a new **Blockchain Type**
  selector that defaults to `evm` so existing workflows are unaffected. Kaspa and UTXO
  accept multiple outputs in a single transaction.
- Light and dark node/credential icons.

### Changed

- Codex `categories` corrected to `Development` + `Data & Storage`. The package
  previously declared `Core Nodes`, which is not in n8n's closed category set and was
  therefore silently invalid.
- Bare errors are wrapped in `NodeApiError` so HTTP context reaches the n8n UI. Errors
  that already carry the API's own response body pass through unchanged.
- `NodeConnectionTypes.Main` replaces the `'main'` string literal for inputs/outputs.
- `Token Amount` and `Token ID` fields render as masked inputs. They are not secrets —
  they are public on-chain values — but n8n's verification rules treat any parameter
  whose name contains "token" as a credential, and the rule's exemption list cannot be
  extended by a package. Renaming was rejected because n8n normalises saved parameters
  against the node descriptor before execution, which would silently discard the value
  in existing workflows; the rename is deferred to the next major with a migration note.

### Removed

- Kaspa dropped from `broadcast`. An `invalid_data` response from that endpoint is the
  API rejecting the *chain*, not a signal that the chain is reachable — the endpoint
  accepts 18 chains and Kaspa is not among them.

### Fixed

- All findings from `@n8n/scan-community-package` (10 → 0). `npx eslint .` had reported
  clean because the scanner builds its own ESLint config, ignores `.eslintrc.js`, and
  loads `@n8n/eslint-plugin-community-nodes`, which the project was not running.
- `blockchainEvents` blockchain defaults now register correctly with n8n's linter while
  still preselecting a chain each event type supports.
